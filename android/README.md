# INPX Server для Android — проверочный APK

Отдельное Android-приложение с существующим Node.js-сервером и веб-интерфейсом.
Минимальная версия — Android 9 (API 28), включая Android 10–11 и 12+. Target SDK 36.
Доступны отдельные APK для ARM32 (`armeabi-v7a`, ARMv7 с NEON) и ARM64 (`arm64-v8a`).
Root и Termux не требуются. Это прототип для установки APK вручную.

Разработка Android-версии: ветка [`android`](https://github.com/AceAsket/inpx-web/tree/android). APK опубликованы отдельно от версий для ПК и Docker: [Android 0.5.0](https://github.com/AceAsket/inpx-web/releases/tag/android-v0.5.0) · [скачать ARM32](https://github.com/AceAsket/inpx-web/releases/download/android-v0.5.0/inpx-server-0.5.0-arm32-debug.apk) · [скачать ARM64](https://github.com/AceAsket/inpx-web/releases/download/android-v0.5.0/inpx-server-0.5.0-arm64-debug.apk). Для приставки с 32-битной Android выбирайте ARM32, даже если её процессор поддерживает 64 бита. Это предрелиз с debug-подписью. SHA256 и сведения о составе находятся в `releases/android-v0.5.0.json`; контрольные суммы доступны также рядом с APK в релизе.

Оба APK используют проверенный снимок backend 1.8.1-rc.4 (`fd1df1ab`) и Node.js 24.22.1. Java/JNI и конвертеры пересобраны для обеих архитектур и API 28. Ветка `android` создана от develop с backend 1.8.1-rc.5; повторная упаковка runtime из этой ветки включит уже эту версию.

## Сенсорный экран и телевизор

В одном APK есть два варианта нативной панели управления сервером:

- **Касания** — экран с прокруткой, карточками состояния и источников, крупной основной кнопкой и быстрыми действиями.
- **Пульт** — две колонки, заметная рамка фокуса, управление стрелками, OK и «Назад». Состояние и адрес доступны с дивана; QR-код позволяет открыть библиотеку на телефоне. Настройки порта и журнал открываются отдельными окнами.

Режим **Автоматически** выбирает ТВ-интерфейс на Android TV / Leanback и сенсорный на телефонах и планшетах. Кнопка режима в правом верхнем углу позволяет сменить выбор вручную; настройка сохраняется. Смена режима не перезапускает сервер. Обновление статуса не перестраивает кнопки и не сбрасывает фокус пульта.

Шапка и кнопки растут вместе с текстом; прокрутка ТВ-колонок ограничена областью между шапкой и нижними подсказками. Рамка фокуса имеет собственный отступ и не требует прорисовки элементов за границами экрана. `scripts/android/check-layout.ps1` проверяет оба режима при масштабе шрифта 100% и 140%, затем восстанавливает исходный масштаб.

Кнопка **Telegram** рядом с настройками и журналом открывает окно сообщества [INPX Web](https://t.me/inpxweb). Ссылку можно открыть на устройстве, скопировать или отсканировать QR-код телефоном. Для управления пультом настроены переходы между всеми тремя кнопками и возврат фокуса после закрытия окна.

В режиме пульта стрелки перемещают фокус, OK открывает действие, «Назад» закрывает диалог. В формах стрелки вверх/вниз переходят между полями; OK в поле открывает экранную клавиатуру. На ТВ-лаунчере отображаются отдельный баннер и иконка. Сенсорный экран для установки не требуется.

Это два интерфейса **управления Android-сервером**. Каталог и читалка продолжают использовать существующий веб-интерфейс. На приставке без браузера каталог удобно открыть на телефоне по QR-коду. Если прошивка приставки не содержит системного выбора папок, приложение сообщает об этом и предлагает SMB.

## Запуск

1. Установить `inpx-server-0.5.0-arm32-debug.apk` или `inpx-server-0.5.0-arm64-debug.apk` из Android-релиза под архитектуру своей Android.
2. Для первой проверки нажать **Запустить демо-библиотеку**. Две тестовые книги находятся в ZIP и 7z.
3. Для собственной библиотеки добавить папку с одним INPX и архивами через **Добавить папку · SD / USB**, либо добавить SMB-источник.
4. Нажать **Запустить сервер**. Кнопка **Открыть каталог** открывает каталог на устройстве. На другом устройстве использовать показанный адрес Wi-Fi и порт (по умолчанию 12380).
5. Перед сменой источников остановить сервер и запустить снова. Основная кнопка меняется на **Остановить сервер** и запрашивает подтверждение; остановка доступна также в уведомлении.

SD/USB должны быть распознаны Android и доступны в системном выборе папки. Выбирать нужно папку библиотеки; Android ограничивает выбор корней некоторых накопителей. Разрешение сохраняется между запусками. Неподдерживаемую файловую систему USB приложение само не монтирует.

Для SMB указать имя/IP сервера (можно `адрес:порт`), имя общей папки, необязательную подпапку, логин, пароль и домен. Подключение выполняется внутри приложения по SMB2/SMB3. Учётные данные хранятся с AES-GCM и ключом Android Keystore; резервное копирование приложения отключено. Книги читаются с правами чтения. Настройки Node.js содержат только идентификаторы источников, без SMB-паролей.

Индекс, журналы и кэш находятся во внутренней памяти приложения. Ограничения кэша: книги 256 МиБ, обложки 64 МиБ. Для чтения архивов используется файловый дескриптор: SD/USB — через SAF, SMB — через `StorageManager.openProxyFileDescriptor`. ZIP и 7-Zip читают по смещению; полного предварительного копирования архива нет. Solid-7z может потребовать чтения и распаковки большого блока.

Сервер работает как foreground service с постоянным уведомлением (`specialUse` на Android 14+). Значок книг статичный: он не изображает загрузку или выгрузку. Остановить сервер можно из приложения или уведомления.

В разделе **Фоновая работа** доступны partial wake lock (включён по умолчанию), автозапуск после включения устройства (выключен по умолчанию) и остановка при отключении питания (выключена по умолчанию). Wake lock не включает экран. После остановки из-за отключения питания сервер запускается вручную. Настройки сна Android открываются отдельной кнопкой; приложение само не меняет исключения энергосбережения.

Состояние запуска хранится атомарно между процессами. При неожиданном завершении Android может восстановить sticky-службу с прежней библиотекой и портом; после трёх запусков за десять минут автоматические попытки блокируются до ручного запуска. Ручная остановка сохраняется и не отменяется автозапуском. Получение BOOT_COMPLETED происходит после разблокировки хранилища; принудительно остановленное через настройки Android приложение сначала нужно открыть вручную.

Только INPX копируется в локальный кэш атомарно после проверки структуры ZIP, размера и CRC содержимого. Последний исправный индекс сохраняется при временной недоступности источника и повреждённом обновлении INPX. Ограничения: 1 ГиБ сжатого и 8 ГиБ распакованного INPX. Служба повторяет проверку недоступных источников раз в минуту, доступных — раз в 15 минут, а после изменения сети или подключения/извлечения накопителя запускает проверку сразу. При отключённом источнике доступны каталог и ранее закэшированные книги. Новый INPX подхватывается существующим механизмом обновления индекса сервера.

## Состояние источников и переподключение

На карточке источника отображается доступность и наличие сохранённого каталога. Окно **Состояние источников** показывает причину ошибки, время проверки и последнего успешного доступа, размер и дату сохранённого INPX, свободное место приложения. Кнопка **Проверить сейчас** проверяет источники без перезапуска сервера; при остановленном сервере проверка не запускает его. Отчёт можно скопировать, он не содержит паролей и SAF URI.

Различаются отключённый накопитель, отозванное разрешение SAF, недоступный SMB-сервер, ошибка входа, отсутствующая общая папка и повреждённый INPX. При отозванном разрешении нужно выбрать папку заново. Настройки подключения изменяются через обычное меню источника и применяются после перезапуска сервера.

После ошибки сети SMB-соединение сбрасывается; операции чтения повторяются один раз. Открытый proxy-дескриптор может восстановить чтение с нужного смещения после перезапуска NAS. Перед продолжением проверяются размер и время изменения архива: изменившийся файл требует нового скачивания. Для SAF устаревшие идентификаторы файлов разрешаются заново внутри выданной папки. Ожидание ответа SMB не удерживает блокировку других источников.

Недоступный источник без локального INPX не мешает запуску остальных. Когда такой источник впервые становится доступен, панель предлагает перезапустить сервер для добавления в каталог. Источники с ранее сохранённым индексом восстанавливаются без перезапуска.

Для постоянного доступа рекомендуется питание и разрешение работы без ограничений. [Doze](https://developer.android.com/training/monitoring-device-state/doze-standby) может приостановить сеть и wake lock; [Low Power Standby](https://developer.android.com/reference/android/os/PowerManager#isLowPowerStandbyEnabled()) также ограничивает foreground service. Поведение конкретной прошивки, длительная работа и реальные USB/SD требуют аппаратной проверки.

Веб-сервер слушает `0.0.0.0` и доступен в локальной сети. Действуют существующие профили и настройки авторизации INPX; первоначальный случайный пароль администратора выводится в журнале. Внешние декодеры JXL/WebP пока не включены.

## Конвертеры ARM32 и ARM64

В APK включены fb2cng 1.9.0, MuPDF 1.27.0 и Kindling 0.45.6, собранные NDK для Android. Доступны FB2 → EPUB, EPUB3, KEPUB, KFX, AZW8, PDF и MOBI. MOBI создаётся как контейнер MOBI7/KF8 с отдельной проверкой структуры. PDF обрабатывает MuPDF; Calibre в Android-сборку не входит, поэтому остальные настольные цепочки конвертации не гарантируются. Одна конвертация выполняется одновременно, очередь ограничена четырьмя заданиями, тайм-аут задания — три минуты.

В ARM32 включены те же конвертеры и 7-Zip. Лимит старого поколения кучи Node.js уменьшен до 256 МиБ (ARM64 — 512 МиБ); это не общий лимит памяти приложения. На старых приставках большие индексы, solid-архивы и конвертация крупных книг требуют отдельной проверки.

Из-за конвертеров APK существенно больше версии 0.2. Выполняемые файлы извлекаются Android из `jniLibs` в разрешённый каталог приложения. Лицензии конвертеров (включая AGPL MuPDF) и Noto OFL находятся в assets; исходные версии и контрольные суммы закреплены в скриптах сборки и `converter-assets.lock.json`.

## Сборка на Windows с WSL Ubuntu

Нужны Node.js 24+ с зависимостями проекта, Java 17 в WSL, `curl`, `unzip`, `make`, `g++`, `python3`. Android Studio не требуется. Команды выполняются из корня репозитория:

```powershell
wsl -d Ubuntu -- env JAVA_TOOL_OPTIONS=-Djdk.tls.client.protocols=TLSv1.2 bash scripts/android/setup-build-env.sh
wsl -d Ubuntu -- bash scripts/android/prepare-converter-tools.sh
wsl -d Ubuntu -- env INPX_ANDROID_ABI=arm64-v8a bash scripts/android/build-native.sh
node node_modules/webpack/bin/webpack.js --config build/webpack.prod.config.js
node scripts/android/prepare-runtime.js
wsl -d Ubuntu -- env INPX_ANDROID_ABI=arm64-v8a bash scripts/android/build-apk.sh assembleDebugAndroidTest lintDebug
# Дополнительный APK для 32-битной Android:
wsl -d Ubuntu -- env INPX_ANDROID_ABI=armeabi-v7a bash scripts/android/build-native.sh
wsl -d Ubuntu -- env INPX_ANDROID_ABI=armeabi-v7a bash scripts/android/build-apk.sh assembleDebugAndroidTest lintDebug
```

`INPX_ANDROID_ABI` по умолчанию равен `arm64-v8a`. `build-native.sh` собирает 7-Zip и все три конвертера выбранной архитектуры с NDK API 28. Результаты: `dist/android/inpx-server-0.5.0-arm32-debug.apk`, `dist/android/inpx-server-0.5.0-arm64-debug.apk` и переносимые файлы `.sha256`. Последовательно выполняйте сборки APK для разных ABI: Gradle использует общий каталог результата.

Инструменты устанавливаются в `~/.cache/inpx-android` внутри WSL; расположение можно изменить через `INPX_ANDROID_TOOLS`. SDK/NDK, Gradle и бинарники не входят в Git. На Linux те же bash-скрипты выполняются напрямую. Для создания демонстрационного 7z скрипт упаковки использует `C:/Program Files/7-Zip/7z.exe` на Windows, `7zz` на Linux или путь из `INPX_7Z`.

Версия Android Node.js и SHA256 закреплены в `runtime.lock.json`; используется fork `fogtape/nodejs-mobile` на Node.js 24.22.1. Источник 7-Zip 26.03 и SHA256 закреплены в `build-sevenzip.sh`. 7-Zip собирается NDK из исходников с отключённым RAR. Скрипт сборки применяет одну проверяемую поправку в `CPP/Windows/FileIO.cpp`: для `/proc/self/fd/3` выполняется `dup(3)`, чтобы использовать уже разрешённый read-only дескриптор Android, а не повторно открывать proxy-файл. Лицензии Node.js, 7-Zip и LGPL включены в APK. APK подписывается локальным debug-ключом Gradle и предназначен для проверки; для распространения нужен постоянный release-ключ.

## Проверки

```powershell
node scripts/android/storage-fs-tests.js
adb install -r dist/android/inpx-server-0.5.0-arm64-debug.apk
adb shell am start -n ru.inpx.server/.MainActivity
adb forward tcp:22380 tcp:12380
# Запустить демо в приложении:
node scripts/android/check-server.js http://127.0.0.1:22380 dist/android/device-http-checks.json
```

Проверка HTTP ждёт готовности индекса, загружает веб-интерфейс, ищет тестовые книги через WebSocket и скачивает их из ZIP/7z. При запуске демо также выполняются нативные проверки, отчёт сохраняется в `files/data/device-checks.json` внутри приложения.

Для отдельного теста SMB можно поднять локальный read-only сервер `scripts/android/smb-test-server.py` (нужен Impacket 0.13.0), выполнить `adb reverse tcp:1445 tcp:1445`, затем в приложении добавить `127.0.0.1:1445`, общую папку `books`, логин `inpx-test`, пароль `android-test`. Эти данные используются только временным тестовым сервером. После проверки сервер остановить и удалить reverse.

ARM64 проверен на Android 16. APK ARM32, а также запуск на Android 9–11 и 12/14 пока проверены только сборкой, Android Lint и анализом бинарников. Физическое устройство с 32-битной Android и реальные SD/USB требуют отдельной проверки.

Результаты проверки на Lenovo TB321FU: [TEST-RESULTS.md](TEST-RESULTS.md).

Проверка двух интерфейсов на подключённом устройстве (не меняет источники и порт, восстанавливает выбранный режим):

```powershell
wsl -d Ubuntu -- bash scripts/android/build-apk.sh assembleDebugAndroidTest
adb install -r dist/android/inpx-server-0.5.0-arm64-debug.apk
adb install -r android/app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w ru.inpx.server.test/ru.inpx.server.UiSmokeInstrumentation
adb pull /sdcard/Android/data/ru.inpx.server/files/ui-checks dist/android/ui-checks
```

Полный тест `adb shell am instrument -w -e background true ru.inpx.server.test/ru.inpx.server.UiSmokeInstrumentation` также запускает семь конвертаций демо-книги, завершает процесс службы для проверки восстановления, проверяет ручную остановку и защиту от цикла сбоев. Источники и пароли не изменяются. Отчёт сохраняется в `files/background-checks.json` внешнего каталога приложения. По завершении instrumentation Android завершает процессы тестируемого приложения; снова откройте панель и запустите сохранённую библиотеку.

Проверка выдачи всех форматов по сети: `node scripts/android/check-server.js http://АДРЕС:12380 dist/android/conversions-http.json ИДЕНТИФИКАТОР_ИСТОЧНИКА --converters`. Короткий управляемый тест Doze: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/android/check-power.ps1 -Base http://АДРЕС:12380`. Он временно выключает экран и симулирует работу от аккумулятора, затем восстанавливает питание и исходное исключение из оптимизации. Перед запуском сервер должен работать; опция остановки при отключении питания должна быть выключена.

Тест переподключения использует отдельный DocumentsProvider из тестового APK и read-only SMB fixture. SAF-провайдер выдаёт URI-разрешение только на сгенерированные тестовые файлы; имитируются отключение, смена document ID и отзыв доступа. Vault и пользовательские источники не меняются. Для SMB запускается контроллер `scripts/android/reconnect-test-server.py ПУТЬ_К_КОПИИ_ДЕМО` в WSL с Impacket 0.13.0. Он создаёт 8-МиБ тестовый файл и управляет только собственным дочерним SMB-процессом: приостановка, отключение, новый запуск. Порты 1445/1446 слушают loopback. После `adb reverse tcp:1445 tcp:1445` и `adb reverse tcp:1446 tcp:1446` выполнить `adb shell am instrument -w -e storage true ru.inpx.server.test/ru.inpx.server.UiSmokeInstrumentation`. Отдельный запуск без UI: `-e storageOnly true`. Отчёт: внешний каталог приложения `files/storage-checks.json`. После теста остановить контроллер и удалить оба reverse. Программная имитация SAF не заменяет проверку физического USB/SD и питания OTG.
