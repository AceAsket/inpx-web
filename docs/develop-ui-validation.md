# Проверка интерфейса после RC.14

Исправления подготовлены в `develop` после опубликованного `v1.8.2-rc.14`.
Исправления включены в `1.8.2-rc.15`; старый образ RC.14 их не содержит.

## Поведение

- Карточки в одном ряду имеют одинаковую высоту и нижнее положение действий.
  Название и авторы занимают до двух строк, серия — одну. Полные данные
  сохраняются в превью. Ряды не наследуют высоту самого большого ряда.
- Поля названия, автора и серии запрашивают соответствующую категорию подсказок;
  лишние группы и исправления старого сервера отбрасываются клиентом.
  Минимум — три символа. Категория и фильтры входят в ключ кэша.
- Поиск в «Обзоре» предлагает книги по названию, сохраняет языковую область
  при поиске и открывает превью по клику или клавиатуре. Первоначальные настройки
  применяются только после получения конфигурации сервера; уже сохранённый выбор
  пользователя не переопределяется.
- В превью видна безопасная текстовая аннотация FB2/EPUB, состояния загрузки,
  отсутствия, ограничения и повтора. Автор и серия — ссылки, у каждого автора
  отдельный переход. Текст книги и изображения ради аннотации не подготавливаются.
- Настройки теста сохраняются в браузере отдельно по профилям: выбор режима,
  источник и свои лимиты. Сохраняется и некорректный ввод, который можно
  исправить после повторного открытия. Пароли и сессии в это хранилище не входят.
- Выбранный стандартный режим проверяется один; сравнение трёх режимов выбирается
  явно. Действующие лимиты сервера показаны отдельно и тестом не меняются.
- Последний завершённый результат содержит проверенные лимиты, краткую оценку
  и причины, например отклик 168 мс при критерии меньше 100 мс. Память и CPU
  имеют пояснения; старый отчёт не выдаётся за результат новой неудачной попытки.
- p95 использует ближайший ранг; один медленный запрос среди пяти не скрывается.
  Таймауты учитываются отдельно, незавершённые пробы остаются single-flight.
  Неизвестная память не подменяется нулём. Старые отчёты доступны с пометкой
  прежней методики, для новой рекомендации нужен повторный тест.

бенчмарка, чтобы проверить интерфейс без нагрузки на библиотеку пользователя.

дополнительно проверяются интеграционным сценарием GitHub Actions; в него
добавлена проверка одного выбранного режима.
