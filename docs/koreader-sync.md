# Синхронизация с KOReader (KOSync)

Сервер реализует API KOSync v1. Внешний сервер KOReader и Redis не нужны.
Включение для конкретного пользователя — **Профили → Настройки → KOReader →
Подключить KOReader**. Будут показаны адрес, имя пользователя и отдельный случайный
пароль. Сохраните пароль: повторно он не отображается. «Создать новый ключ» отзывает
старый, «Отключить» закрывает доступ и удаляет собственные записи KOSync профиля.
Обычный пароль профиля для KOSync не подходит; гостевой профиль подключить нельзя.

В KOReader откройте **Синхронизация прогресса**, укажите свой сервер
`https://ваш-сервер/kosync` (с префиксом пути INPX, если он настроен), выберите
**Войти**, а не регистрацию, и введите выданные данные. Сопоставление документа —
**по содержимому**, не по имени файла. Желательно включить автоматическую
синхронизацию и получение позиции перед отправкой.

Один раз скачайте эту книгу **через этот сервер после подключения KOSync**,
например из OPDS, в несжатом FB2/EPUB/PDF/DJVU. Сервер вычислит такой же частичный
MD5 фактически скачанного файла, как KOReader, и свяжет его с UID каталога. Для
FB2.ZIP распакуйте книгу и скачайте также несжатый FB2 через сервер: ZIP не
сопоставляется автоматически. При замене/конвертации файла скачайте новый вариант
заново. Совпавшее имя или название книги не является доказательством соответствия.

## Что синхронизируется

- Между устройствами KOReader сохраняются его исходный указатель, процент, устройство
  и серверное время последней принятой отправки, даже для книг вне каталога INPX.
- **FB2:** позиция в обе стороны между KOReader и веб-читалкой — до начала абзаца.
  Сервер сопоставляет xpointer KOReader с цитатой в тексте. Номера страниц разных
  читалок не используются. Приложение, которое синхронизирует обычный прогресс
  INPX, получает ту же позицию.
- **EPUB/PDF/DJVU:** из KOReader в INPX переносится процент. Обратного преобразования
  процента в xpointer EPUB или номер страницы PDF пока нет; между KOReader исходный
  указатель продолжает синхронизироваться.
- Если одинаковый скачанный файл относится к разным UID каталога, автоматическая
  привязка считается неоднозначной и веб-прогресс не меняется.
- Прочитанность списков, закладки, заметки и положение аудиоплеера KOSync не меняет.

Если после последнего обмена позиция изменилась в веб-читалке, новая отправка
KOReader не затирает её: сначала получите актуальный прогресс. Старые открытые
веб-вкладки защищены существующими проверками ревизии. Сброс прогресса защищён
поколением данных. Сам протокол KOSync не передаёт исходное время офлайн-чтения
или индивидуальную ревизию клиента: полностью определить порядок конкурирующих
офлайн-изменений нельзя. Между KOReader применяется последняя принятая отправка.

Проверка существования профиля и запись выполняются в одной транзакции: удаление
пользователя во время чтения или индексации FB2 не перенаправляет запись гостю.

Текстовый мост ограничен FB2 до 64 МБ, 50 000 блоков и примерно 2 млн символов.
Индекс читается потоком и строится только по запросу синхронизации скачанной книги.
При неподдерживаемом указателе или ошибке индекса остаётся синхронизация между
KOReader без изменения веб-прогресса. Дисковый кэш текстовых индексов ограничен
128 файлами / 128 МБ и восстанавливается из библиотеки. Все скачанные книги заранее
не читаются. Привязок не более 8192, записей позиции не более 2000 на профиль;
при превышении удаляются самые старые.
Файл состояния ограничен 32 МБ: при заполнении новое обновление отклоняется,
последняя корректная версия файла сохраняется.

## Запуск и доступ

`INPX_KOSYNC_ENABLED=false` выключает все маршруты KOSync и создание новых ключей
при запуске контейнера. По умолчанию маршруты доступны, но доступ к прогрессу
появляется только после создания ключа в профиле. Общие настройки proxy/SSO и
ограничения доступа к серверу сохраняются; KOSync их не обходит. При внешнем
доступе используйте HTTPS: хеш пароля в протоколе является ключом доступа.

Ключи (только проверочные хеши), привязки и позиции хранятся в
`<dataDir>/kosync.json`, текстовый кэш — в `<dataDir>/kosync/`, вне публичной папки.
Для резервной копии берите весь каталог данных; экспорт отдельного профиля через
интерфейс не переносит ключи KOSync. При удалении профиля его старый ключ перестаёт
проходить проверку, даже если запись осталась в файле KOSync.

Маршруты: `GET /kosync/users/auth`, `PUT /kosync/syncs/progress`,
`GET /kosync/syncs/progress/:document`, `GET /kosync/healthcheck`.
Регистрация через `/users/create` закрыта; ключ выдаётся только в профиле.
Проверки протокола, изоляции профилей, перезапуска, отзыва ключа и текстового моста
входят в `npm run test:release`. Проверка на физическом KOReader требует устройства.
