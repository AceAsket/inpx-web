# OPDS 2.0

Доступен начиная с `1.8.2-rc.18` по `/opds/v2`, персональный каталог —
`/opds/v2?user=<profileId>`. Для собственного `opds.root` добавьте к нему
`/v2`; префикс приложения сохраняется. Завершающий `/` также поддерживается.
Включение задаётся существующей настройкой `opds.enabled`.

`/opds` остаётся OPDS 1 в XML/Atom. Новый адрес выдаёт
`application/opds+json`, карточка `/opds/v2/book?uid=…` — отдельную
публикацию `application/opds-publication+json`. Поддерживаются GET и HEAD.
Идентификаторы публикаций — URI `urn:inpx:book:…`; исходный UID каталога
сохраняется в параметре `uid` ссылки карточки.
Режим POST для Tolino относится только к OPDS 1.

Поддерживаются авторы, серии, названия, жанры, поиск, общие подборки,
опубликованные личные списки, продолжение чтения и маркеры ◔ ◑ ◕ ⬤.
Публикации содержат авторов, язык, серию, жанры, обложки, ссылку на карточку
и доступные форматы скачивания. Предпочтение формата профиля влияет на
порядок ссылок. Файл конвертируется при скачивании, а не при чтении ленты.

Ссылка `search` использует URI template с обязательным параметром `query`:
`/opds/v2/search{?query}`. В персональном каталоге шаблон сохраняет `user`.
Переходы остаются в JSON-каталоге. Поиск и полки используют ссылки
`next`/`previous`; большие списки публикаций разделены по 100 книг с
параметром `v2page`. Сериализуются записи выбранной страницы.

Выдача использует уже полученные строки индекса: без парсинга XML-ленты,
дополнительных запросов БД на каждую строку или чтения файлов книг.
Полная карточка использует прежний путь получения метаданных книги.

Авторизация, защита профилей, Basic Auth и ограничения попыток входа
общие с OPDS 1. Переходы сохраняют проверенный профиль, персональные ответы
имеют `Cache-Control: private, no-store`. Отключённый или неизвестный
профиль не превращается в профиль администратора.

Синхронизация KOReader использует отдельный [KOSync API](./koreader-sync.md).
Для FB2 позиция передаётся в обе стороны; для EPUB/PDF/DJVU — процент
из KOReader в INPX. Для MOBI моста позиции с веб-читалкой пока нет.
Endpoint OPDS Progression пока не реализован.

Спецификация: [OPDS Catalog 2.0](https://specs.opds.io/opds-2.0.html).
Ответы каталога и публикаций, включая пустой поиск, расширенные метаданные
и пагинацию, проверены по официальным JSON Schema OPDS и Readium.
`scripts/opds2-tests.js` проверяет метаданные, форматы, изоляцию прогресса,
экранирование и объём сериализации. `scripts/opds2-integration-test.js`
проверяет настоящий HTTP API: оба каталога, поиск, карточку, скачивание,
личные полки и Basic Auth. Проверка конкретного клиента на устройстве
остаётся отдельной от проверки серверного протокола.
