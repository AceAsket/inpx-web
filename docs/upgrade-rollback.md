# Обновление и откат

Начиная с 1.8.1-rc.10 перед первым запуском каждой новой версии сервер сохраняет
`config.json`, `secret.key`, `reading-lists.json`, `discovery-cache.json` и каталог
`public` в `<dataDir>/.upgrade-backups/<время>-<новая-версия>/`.
Снимок создаётся до миграции секретов, записи профилей и замены веб-интерфейса.
Повторный запуск той же версии его не перезаписывает. Если копирование не удалось,
запуск прерывается, исходные файлы остаются на месте. Отсутствующие файлы в снимок
не добавляются. Библиотека, поисковый индекс, аудио и кэш книг не копируются.

Снимки содержат пароли профилей и ключ шифрования. Храните их вместе с закрытыми
данными приложения; не публикуйте каталог. Старые снимки автоматически не удаляются.
Объём зависит в том числе от пользовательских файлов в `public`.
Отдельная резервная копия тома и конфигурации контейнера перед обновлением остаётся
полезной: автоматический снимок не включает окружение Docker и файлы вне каталога данных.

## Почему для отката недостаточно заменить образ

RC9 не знает фильтр `ratingCount`. При записи профилей он может удалить этот фильтр
или целиком умную полку, где других фильтров нет. Старый установщик интерфейса также
удаляет весь `public`, если его версия отличается. Поэтому откат выполняется
с восстановлением снимка до обновления, включая прежний `public`.
Созданные после снимка позиции чтения, полки и настройки при таком откате не сохранятся;
сначала сделайте отдельную копию текущего состояния.

## Пример отката контейнера

Пример рассчитан на стандартный `config.json` внутри тома данных. Если конфигурация
хранится отдельно, восстановите её в путь `configFile` из `manifest.json`.
Сначала выберите нужный снимок и проверьте его манифест. Контейнер должен быть остановлен
на всё время копирования. Используйте прежний сохранённый контейнер или его конфигурацию,
чтобы сохранить порты, сеть, переменные окружения и подключения томов.

```sh
docker stop inpx-web
inpx_data=/mnt/user/appdata/inpx-web
inpx_snapshot="$inpx_data/.upgrade-backups/ИМЯ_СНИМКА"
cat "$inpx_snapshot/manifest.json"
# Перед восстановлением сохраните текущее состояние в отдельном каталоге/снимке NAS.
```

Восстановите перечисленные в `manifest.json` файлы и `public` из снимка в том данных.
Если какого-либо из этих файлов до обновления не было, удалите созданный новой версией
экземпляр при восстановлении. Удалите `<dataDir>/.upgrade-version.json`, чтобы следующий
запуск новой версии снова сделал снимок. Затем запустите прежний контейнер.
Сверьте профили, позиции чтения, закладки, полки и пользовательскую читалку.
Обычный импорт резервной копии профиля не восстанавливает `public` и конфигурацию Docker.
