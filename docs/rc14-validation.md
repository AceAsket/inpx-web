# Проверка 1.8.2-rc.14

Кандидат исправляет обнаруженное на RC.13 падение DB worker во встроенном
бенчмарке, ограничивает подсказки и галерею, добавляет Telegram-прокси и исправляет
замечания к интерфейсу. Работа ведётся непосредственно в `develop`.
Опубликованные RC.13 и стабильный `latest` не заменяются.

## Уже выполнено

- Локальные release smoke: **370 проверок**, exit 0, включая реальную Jemba-пробу
  с одной прочитанной строкой, исчезнувший ID, single-flight после таймаута,
  отказ worker, readiness и доступность метрик при отказе базы.
- Тесты озвучки и плеера: exit 0, включая WebSocket, доступ и HTTP Range.
- Production-сборка клиента: exit 0, начальные JS/CSS 1 017 590 байт.
- Реальный Chromium: превью и отдельная полная карточка, светлая/тёмная темы,
  загрузка автора, ввод и валидация своих лимитов, передача параметров теста,
  отмена, отображение CPU и отсутствие переполнения карточек — PASS.
- Прогресс отзывов: проценты двух измеримых этапов, неизвестные объёмы без
  процентов, отсутствие продвижения от времени, поздние кадры, смена книги,
  ошибка, повтор и сервер без progress-кадров — PASS на desktop и mobile.
- Независимое ревью управления DB worker, проб бенчмарка и своих лимитов
  не выявило блокирующих дефектов.
- Подсказки: 3 Unicode-символа, отсутствие запросов для двух символов,
  поиск до ответа, отсутствие polling, частичная выдача, клавиатура, превью
  и область фильтров — PASS. На 30 005 книгах получены 6 подсказок за 65 чтений
  строк; повторный запрос не читает строки. Это локальная проверка алгоритма,
  а не оценка задержек NAS.
- Галерея: извлечено 18 изображений из 40 вместо подготовки всех 40, отдельный
  кэш и объединение запросов, 2/8/32 МиБ ограничения, SAX text/CDATA буферы,
  неверный размер ZIP entry, смена библиотеки и повторное чтение — PASS.
  Реальный браузер проверяет 20 встроенных PNG → 18 превью и сообщение ограничения.
- Telegram: реальные локальные HTTPS/CONNECT/SOCKS5/5h, авторизация,
  DNS/IPv6, system/direct/custom, NO_PROXY, native Node env-agent, все пути
  Bot API, шифрование и повторная загрузка пароля — PASS. Для каждого из четырёх
  протоколов проверены timeout/abort/destroy зависшего handshake: сокеты закрыты.
  Обращений к Telegram и отправок реальным пользователям не выполнялось.
- Форма прокси: сохранение, сохранённый пароль, очистка, ошибочный скрытый draft,
  смена режима и проверка маршрута; отсутствие пароля в API и localStorage,
  поля внутри диалога 320 px — PASS.
- Production audit: 0 moderate/high/critical; 2 прежние low.

Проверки интерфейса используют изолированные локальные библиотеки. Форму
своих лимитов дополнительно проверяет синтетический API; расход CPU/RAM там
не является измерением пользовательского сервера. Обычные чтения опубликованной
RC.13 на восстановленном стенде описаны в [отчёте стенда](./rc13-stand-review.md).
