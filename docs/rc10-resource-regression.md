# Исправление нагрузки RC10

В RC10 подготовка `catalog_lookup` запрашивала имена через `offset`, `limit` и `map`. В используемой JembaDB ограничение и проекция применяются после чтения и глубокого копирования всех подходящих строк. Поэтому каждая порция повторно читала целую таблицу, включая большие `bookIds`. Стоимость росла квадратично. Дополнительные строки на каждую пару «слово — имя» оставались в открытой таблице после подготовки. Это подтверждённые причины лишних CPU и памяти; само по себе высокое RSS не доказывает утечку.

В RC11 курсор базы читает по 1000 имён и передаёт только `id` и `name`. Слова внутри порции объединены в списки идентификаторов. Между порциями есть пауза, а обращения к базе проходят через ограничение фоновой работы с приоритетом чтения и карточек. Индекс запускается по первому запросу подсказок, не открывается общим `openAll` и закрывается через 30 секунд без чтений. Незавершённая сборка освобождает курсоры и таблицу. Формат RC10 автоматически перестраивается при первом запросе; книги и основной каталог не изменяются.

Второй дефект воспроизведён в браузере: компонент читалки сохраняется `KeepAlive` и следил за `bookUid` общего маршрута. В новом дизайне страницы карточек тоже содержат этот параметр. После первого посещения читалки переход к другим карточкам мог запускать скрытую загрузку документа и пагинацию. Теперь ключ загрузки существует только у активной читалки; уход инвалидирует текущие операции, а поздний ответ проверяется до разбора документа. Сервер объединяет одинаковые одновременные запросы и удаляет выполненные обещания, не создавая кеш больших документов в памяти.

## Воспроизводимый замер

`node scripts/catalog-resource-benchmark.js 200000` создаёт отдельную временную базу: 200 тысяч названий, по 20 тысяч авторов и серий, по 20 идентификаторов книг в исходных строках. Запрос проверяет все 200 тысяч совпадений общего слова. Данные библиотеки и работающего сервера не используются. Для сравнения старую версию `server/core/CatalogLookupIndex.js` из тега `v1.8.2-rc.10` можно передать вторым аргументом. Запускайте варианты последовательно.

Локальный замер Windows / Node.js 24.22.1, без принудительной сборки мусора:

| Метрика | RC10 | RC11 |
| --- | ---: | ---: |
| Прочитанные исходные строки | 20 640 000 | 240 000 |
| Подготовка, мс | 44 004 | 9 475 |
| CPU процесса, мс | 55 579 | 3 547 |
| Пиковый RSS процесса, МиБ | 1 063 | 519 |
| Запрос общего слова, мс | 610 | 86 |

Это один синтетический сценарий, не полная библиотека fLibrary и не сравнение общего потребления контейнеров. RSS включает временную базу и рантайм; исходный RSS перед подготовкой отличался между процессами (402 и 390 МиБ). Освобождение ссылок не обязывает V8 сразу вернуть всю память ОС. Чтобы наблюдать штатное закрытие таблицы, задайте `INPX_BENCHMARK_IDLE_MS=31000`; итог содержит `lookupTableOpen`.

## Регрессионные проверки

`scripts/catalog-discovery-tests.js` проверяет один проход по исходным строкам, автора со 100 тысячами книг, границы порций, разреженные ID, пересечение слов, компактность записей, закрытие и повторное открытие, миграцию старого формата и замену библиотеки. В `scripts/book-card-tests.js` проверяются совместная подготовка одновременных запросов, отсутствие сохранённых обещаний с большими документами, очистка после ошибки и смены поколения библиотеки. Обычное чтение не ожидает индекс отзывов.

Браузерный сценарий проверяет отсутствие индекса после запуска, первую подготовку подсказок, переход из новой карточки в чтение и возврат, страницы авторов и серий. Отдельный сценарий оформления проверяет первое и повторное чтение EPUB через FB2. Эти проверки не заменяют длительный замер на сервере с реальной библиотекой.
