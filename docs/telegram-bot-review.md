# Telegram-бот: проверка и план доработок

Проверка 8 ноября 2026 года, база — `1.8.2-rc.18`.
Ниже исходные ограничения RC18 и результаты исправлений RC19.
В опубликованный RC18 эти изменения не входят. Исправления `/ebook` описаны
в [документации простого интерфейса](ebook.md#изменения-rc19).

## Что проверено

Прочитаны обработчики команд, привязка профиля, polling, подготовка/отправка
файла, общие форматы, подписки и сетевой транспорт. Прошли шесть сценариев
интерактивного бота и девять проверок IPv4/IPv6 и прокси. Они используют
тестовый API и локальные HTTPS/CONNECT/SOCKS-серверы. Сообщений настоящим
пользователям и обращений с рабочим токеном не было.

Подтверждены одноразовая привязка, изоляция чатов и профилей, срок кнопок,
отмена при отвязке, сохранение offset после перезапуска, настройка формата
профиля, защита секретов в ошибках и отказ от прямого соединения при
неработающем явно заданном прокси. Отправка использует файловый поток.
Одновременно готовятся до четырёх книг, по одной на чат; действуют очереди
общего runtime. Карты кнопок/привязок/частоты имеют ограничения размера
и срока жизни; это не заменяет длительный замер памяти на рабочем сервере.

## Исправлено в RC19

- `/lists` получает названия полок без запросов книг. Открытие полки загружает
  восемь книг; непрочитанная умная полка просматривает не более 200 записей
  за запрос и предлагает продолжение. Курсоры позволяют вернуться назад.
- Поиск использует настоящий индекс каталога, допускает короткие названия
  и предлагает поля «По названию / По автору / По серии». Результаты идут
  страницами по восемь книг; отдельный индекс подсказок не запускается.
- `/following` показывает все доступные результаты по страницам, а перелистывание
  не повторяет дорогую проверку подписок и не расходует её лимит обновлений.
- Общая отправка в Telegram ограничивает подпись 1024 единицами UTF-16,
  сохраняя целые emoji. Это защищает и отправку из веба, и интерактивного бота.
- Если в личном профиле уже есть уникальный положительный `Chat ID`, отдельная
  ссылка не нужна. Бот автоматически сохраняет эту связь. Группы не получают
  доступ к профилю. Новые дубликаты личных ID при включённом боте отклоняются
  настройками; старые неоднозначные записи не выбирают первый профиль.
  Подтверждённая одноразовой ссылкой связь имеет приоритет над конфликтующим
  ID из другого профиля. Смена ID отзывает старую связь и ожидающие отправки;
  `/unlink` сохраняет отключение после перезапуска. Ссылка остаётся запасным
  способом подключения. Указание Chat ID теперь явно описано в форме профиля
  как предоставление доступа боту, а не только адрес доставки.

Прошли 442 регрессионные проверки, в том числе поиск бота через настоящую
базу каталога. Целевая Telegram-проверка включает 11 сценариев бота,
четыре проверки IPv4/IPv6 и локальной HTTPS-отправки и шесть проверок прокси.
Длинные подписи с кириллицей и emoji проверены в настоящем multipart-запросе
к локальному HTTPS-серверу. Сборка клиента и браузерная проверка профилей прошли.

## Проверка команд в RC20

Дополнительная проверка RC20 запускает настоящий цикл `getUpdates` с тестовым
API и только заданным в профиле Chat ID: `/start`, `/help`, `/search`,
`/reading`, `/lists`, `/favorites`, `/following`, открытие книги и получение
EPUB. Одноразовая ссылка не создаётся. Чужой чат и группа не получают доступ
к личным данным; команды `setWebhook`/`deleteWebhook` не вызываются.
Все 12 сценариев бота проходят без рабочего токена и отправки настоящих сообщений.

## Исходные проблемы RC18

| Приоритет | Случай и наблюдение | Исправление и критерий проверки |
| --- | --- | --- |
| P1 | `/lists` вызывает `getReadingLists`, который раскрывает все умные полки до пагинации. Открытие одной умной полки также сначала получает все UID. На синтетике: три полки по 10 000 книг, 30 запросов к таблице книг и 30 000 UID только для меню полок. | Использовать общий механизм `EbookShelves.lists/page`: меню без выполнения фильтров, страница из восьми книг, ограниченный проход непрочитанных до 200 строк и курсор продолжения. Тест должен запрещать вызов `smartShelfEntries` из этих команд и проверять доступ к чужой полке. |
| P2 | Поиск построен на `CatalogDiscovery.suggest`. Для `Яд` реальный обработчик подсказок возвращает пустую выдачу до обращения к БД, а бот пишет «Ничего не найдено». Даже при `limited: true` показывает до шести книг в группе без предупреждения и продолжения. | Полноценный поиск с выбором «Книги / Авторы / Серии» и страницами по восемь результатов. Короткий отправленный запрос должен проверяться поиском, а ограниченная выдача — явно обозначаться. Не запускать полный индекс подсказок или загрузку всех книг. |
| P2 | `/following` всегда берёт первые 12 книг. Из 20 доступных новинок восемь нельзя открыть; кнопки следующей страницы нет. | Добавить пагинацию новинок; проверить 0/1/12/20 результатов, возврат назад и смену каталога во время запроса. |
| P2 | Подпись `sendDocument` формируется из полного шаблона без ограничения. Синтетический список авторов дал 1508 символов. Telegram допускает до 1024 символов подписи. | Ограничить подпись в общей отправке `WebWorker.sendBookToTelegram`, сохраняя Unicode и корректность emoji. Проверить отправку из веба и интерактивного бота с длинными авторами и пользовательским шаблоном. |

Лимит подписи и облачной отправки файла проверен по
[официальному Bot API](https://core.telegram.org/bots/api#senddocument).
Число прочитанных UID в таблице выше — результат изолированной синтетики,
а не замер RSS/CPU пользовательского контейнера.

## Дальнейшие доработки

1. **Замеры стенда.** После установки следующего выпуска измерить RSS и CPU
   на реальных больших полках и нескольких чатах. Локально проверены отсутствие
   запросов книг из меню, восемь результатов страницы и предел 200 записей
   при проходе непрочитанных.
2. **Управление отправкой.** Добавить «Отменить подготовку»
   через уже существующий AbortController задания. Показывать состояния
   очереди, конвертации и отправки; процент использовать только при наличии
   измеримого объёма. Ошибки различать: формат, размер, сеть/прокси,
   истёкшая привязка. Не повторять автоматически запрос с неясным исходом
   отправки, чтобы не доставить одну книгу дважды.
3. **Карточка и личная библиотека.** Аннотация по отдельной кнопке через
   ограниченный `getBookPreview`, кнопки авторов, год и жанры, выбор личной
   полки и снятие отметки «Прочитано». Прогресс показывать из того же
   источника, что веб и OPDS. После этого — команда рекомендаций при
   непустой персональной подборке; без фоновой подготовки всей библиотеки.

Изменения транспорта и новые обязательные настройки для этих задач
не требуются. Сначала полезнее исправить нагрузку и доступность результатов,
затем расширять карточку и рекомендации.
