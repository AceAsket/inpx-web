# Исправления по аудиту 1.7.7

Ветка: `develop`. Первый этап исправлений; номер версии остаётся 1.7.7 до подготовки следующего релиза.

## Сделано

- Полные бэкапы сохраняются в `DATA_DIR/backups`. Скачивание через `/admin-backups/:fileName` (с учётом rootPathStatic) требует действующих HTTP-сессии и токена профиля администратора. Секреты не передаются в URL. Старый публичный `/book/backup` закрыт, включая кодированные пути; старые файлы остаются на диске.
- Операции ReadingListStore выполняют чтение, изменение и атомарную запись в одной очереди на файл. Очередь общая для экземпляров хранилища внутри процесса, вложенные вызовы не блокируют сами себя. Прежняя защита поколений сброса прогресса сохранена. Это не межпроцессная блокировка: несколько серверов не должны одновременно использовать один reading-lists.json.
- `secret.key` публикуется атомарно без замены уже созданного ключа, включая одновременный старт нескольких процессов. Расшифровка без ключа завершается понятной ошибкой и не создаёт новый ключ. Конфиг сохраняется через очередь, временный файл, fsync и rename; ошибка замены сохраняет предыдущий файл.
- HTTP-сессии и токены профиля ограничены 30 днями с момента создания и 7 днями неактивности. Каждый реестр ограничен 10 000 записями; при создании сессий просроченные записи периодически удаляются. Health, metrics и обычные запросы ресурсов без cookie не создают сессий. Повреждённые cookie и многобайтовые подписи не вызывают исключений.
- Смена пароля или логина, удаление профиля и восстановление профилей из полного бэкапа отзывают соответствующие токены. Проверка пароля и выдача токена сериализованы со сменой учётных данных. Обычные изменения имени/настроек сохраняют вход. Cookie локального резервного входа при proxy-auth тоже проверяет серверный срок 30 дней; старый формат потребует повторного входа.
- При смене логина защищённого профиля необходимо повторно указать пароль: текущий формат хеша зависит от логина. Это предотвращает потерю доступа без изменения формата существующих хешей.
- FileDownloader проверяет TLS по умолчанию, поддерживает явно заданный CA через HTTPS agent, ограничивает время запроса и простоя потока. Превышение размера, отмена и таймаут уничтожают поток и закрывают соединение; пользовательские заголовки сохраняются.

## Проверки

`node scripts/release-smoke-tests.js`: **36/36**, Node **24.19.0**, Windows.

Включены реальные параллельные записи и 8 дочерних процессов создания ключа, ошибка замены конфига, HTTP-проверки скачивания бэкапа, отзыв/истечение сессий, зависающие локальные HTTP-серверы и локальный HTTPS с недоверенным сертификатом. Сертификат и ключ в scripts/fixtures/tls — публичные тестовые данные.

ESLint для новых вспомогательных модулей, SecretStore, FileDownloader и нового набора регрессионных тестов прошёл. `git diff --check` прошёл.

Отдельный запуск на Node 16.16.0 из локального кэша pkg отклонён автоматической проверкой выполнения команд (`blocked by policy`). Совместимость с релизным рантаймом этим запуском не подтверждена. Публикация релиза, Docker-образа и обновление стенда в этот этап не входят.
