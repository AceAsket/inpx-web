# Этап 3: ограничения конвертации и OPDS

Ветка `develop`, номер версии остаётся 1.7.7.

- Общая очередь конвертации: 2 активных задания, до 16 ожидающих. По умолчанию ожидание и выполнение ограничены 120 секундами каждое. Настройки config.json и Docker-переменные описаны в README.
- Ограничение времени распространяется на команды одного задания, включая проверку конфига fb2cng и промежуточные конвертации. По таймауту завершается дерево процессов: отдельная группа процессов в Linux/macOS, taskkill /T /F в Windows. stderr хранится в пределах последних 64 KiB.
- Результат создаётся во временном файле и публикуется через rename только после успеха. Ошибка не оставляет частичный кэш и не удаляет предыдущий готовый файл. Временные копии исходника уникальны для каждого задания, чтобы разные форматы одной книги не удаляли общий временный входной файл.
- OPDS использует отдельный от веб-входа лимит неудачных попыток по IP, общий для глобального пароля и защищённых профилей. Превышение возвращает 429 и Retry-After; обычный запрос без Authorization не расходует лимит. Повторная проверка после чтения профиля закрывает обход лимита пачкой параллельных запросов.
- Успешный вход в один OPDS-профиль не обнуляет ошибки по другим профилям. В метриках появился kind=opds. Счётчики ошибок входа очищаются по сроку и ограничены 10 000 IP-бакетами; при заполнении новые источники временно получают отказ.

Проверки: **42/42** release-smoke-тестов на Windows/Node 24.19.0. Новые сценарии проверяют параллельность, переполнение и истечение очереди, восстановление после ошибки, реальное завершение дочернего процесса конвертера, ограничение stderr, атомарную публикацию кэша и последовательные/параллельные HTTP-попытки входа в OPDS. Windows-бинарник пересобран и прошёл индексацию тестовой библиотеки, health, веб-интерфейс, OPDS и WebSocket. ESLint без ошибок; остаётся старое предупреждение о длине строки в Security.js. Результат CI следует проверять для отправленного коммита в GitHub Actions.

Следующие задачи исходного аудита: уменьшение и разделение лимитов WS/импорта, миграция хешей паролей на scrypt, транзакционное восстановление полного бэкапа, расширенные браузерные тесты, автоматическая публикация Docker и диагностика.

Повторная проверка CI выявила падение Windows-бинарника на коротких путях 8.3 (`RUNNER~1`): известная [регрессия libuv в Node 24](https://github.com/nodejs/node/issues/63638). Каталог данных теперь создаётся и преобразуется через `realpath.native` до запуска наблюдения JembaDb. Поскольку pkg 6.22.0 подменяет native-вариант обычной JS-функцией, сборка сохраняет настоящую native-функцию для внешних файлов, оставляя обработку виртуальной файловой системы pkg. Патч применяется повторно безопасно и останавливает сборку, если структура упаковщика изменилась. Локальный тест с `TEMP=...\INPX-S~1` воспроизвёл аварийное завершение старого бинарника; исправленный бинарник прошёл индексацию, health, веб-интерфейс, OPDS и WebSocket в том же окружении.
