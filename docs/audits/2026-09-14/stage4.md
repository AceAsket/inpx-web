# Этап 4: лимиты запросов, пароли и восстановление

Ветка `develop`; версия пока 1.7.7.

- WebSocket больше не использует лимит скачивания INPX в 500 MiB. Обычные команды ограничены 1 MiB, импорт JSON — 16 MiB, ZIP — 32 MiB до base64. Настройки читалки/профиля допускают 6 MiB для существующей загрузки фонового изображения до 4 MiB. Лимиты настраиваются через config.json и окружение, с верхними границами. До 8 активных запросов на соединение, 64 на сервер и одного крупного сообщения одновременно. Двоичные кадры отклоняются. Неверный JSON и JSON-скаляры дают контролируемую ошибку.
- Импорт списков ограничен 1000 списками и 100 000 записями книг. ZIP проверяется по составу, уникальности имён, JSON, ключу шифрования и суммарному распакованному размеру (64 MiB по умолчанию). При распаковке проверяется и фактический объём потока. Проверка и расшифровка выполняются до замены рабочих файлов.
- Новые пароли: асинхронный scrypt, случайная соль 16 байт, ключ 32 байта, N=16384, r=8, p=5. Это один из [вариантов OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html). Одновременно допускаются четыре вычисления, пароль ограничен 4096 байтами. Формат версионирован; параметры из непроверенного хеша не исполняются. Старые SHA-256 хеши мигрируют под блокировкой файла после успешного веб/OPDS-входа. Смена логина после миграции сохраняет пароль. Клиент больше не может передать готовый passwordHash вместо пароля.
- Создание и восстановление полного бэкапа используют общие блокировки файлов. Замена файлов сопровождается журналом прежних данных, записанным до первой замены. Ошибка записи вызывает откат; незавершённая операция откатывается при следующем запуске до чтения секретов. Если сам откат не удался, журнал сохраняется, а дальнейшие операции с этими файлами блокируются до перезапуска. Это проверено для завершения процесса; отказ оборудования и потеря питания отдельно не моделировались.
- После успешного восстановления сбрасываются сеансы профилей и корректно обновляются оба кэша витрины. Прогресс получает новое поколение, чтобы старые вкладки не перезаписали восстановленные данные. Локальные пути хранилища сохраняются, секреты записываются в зашифрованном виде. Для применения настроек маршрутов и библиотек по-прежнему нужен перезапуск.

Проверки: 46 smoke/regression-тестов, включая реальный WebSocket (ошибка размера, код 1009, восстановление после неверного запроса), переполнение обработки, миграцию OPDS-пароля и повторное открытие хранилища, повреждённый JSON, ZIP с превышением распакованного размера, неверный ключ, ошибку записи и принудительный выход дочернего процесса между заменами файлов. Восстановление после выхода проверяется через ConfigManager.load в новом процессе. Windows-бинарник проверен на коротком пути 8.3. В headless Chromium проверены открытие коллекции, карточка книги и мобильная ширина, без ошибок страницы.

ESLint новых модулей и новых тестов проходит; в крупных существующих WebWorker.js и config/index.js остаются прежние замечания линтера. Финальный статус сборок Windows/Linux и Docker Lite доступен в GitHub Actions для отправленного коммита.
