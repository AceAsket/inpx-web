# Какие настройки Rust-сервера можно менять из админки

Проверена ветка `develop`, коммит `64424087`, 22 ноября 2026 года. Docker и Linux standalone используют один Rust-сервер. В Docker начальную команду также формирует [entrypoint](../../docker-entrypoint.sh). Проверки работающего процесса выполнены на Linux standalone с отдельной библиотекой, через HTTP, WebSocket и Caddy.

## План внедрения

1. Добавить гостевой режим и доверенные сети в админку. Сохранять политику целиком и проверять уже открытые соединения. Показывать администратору TCP-адрес и настройки, заданные окружением.
2. Подключить расписание проверки INPX и предел чтения книги для ISBN. Использовать новый предел со следующей подготовки.
3. Обновлять настройки читалки, конвертеров и обложек во время работы. Синхронизировать форматы скачивания с OPDS и лёгкой читалкой. Сохранять общую очередь при смене параметров конвертации.
4. Добавить дополнительные лимиты очередей и теста производительности. Поля можно сбросить к значениям профиля, если для категории допускается настройка профилем.
5. Сохранять параметры Silero и применять их к новым заданиям. Хранить ключ зашифрованным. Выданные ссылки и уже поставленные в очередь задания сохраняют возможность завершиться.
6. Проверить переключение на открытой вкладке, обновление CIDR через Caddy, запись на диск, приоритет окружения и повторный запуск.

Проверки реализации прошли в двух профилях Chromium и на Linux standalone с Caddy. При запрете гости теряют поиск и прямое скачивание. При повторном разрешении открытая вкладка возвращается в каталог. После удаления сети Caddy существующий WebSocket закрывается, а новый получает HTTP 403. Отдельная проверка Silero подтвердила, что активное задание завершается со своей конфигурацией, а подписанная ссылка на результат продолжает работать после отключения озвучки.

Следующим шагом добавлены режим OPDS и общие подборки, YAML и аргументы fb2cng, переключатель KOReader, ограничение попыток входа и настройки Audiobookshelf и Prometheus. В работающем процессе проверены смена маршрута метрик и отзыв старых токенов. При смене лимита входа счётчики сохраняются. Режим входа и заголовок SSO меняются с проверкой текущего сеанса администратора. Адрес, каталог данных, конфигурация и источники, переданные при запуске, отображаются в админке.

## Что уже применяется

| Группа | Когда изменение вступает в силу |
| --- | --- |
| Профиль ресурсов | Админка пересчитывает лимиты работающих очередей, включая конвертацию и обработку обложек. Уменьшенный лимит регулирует допуск следующих задач. [Применение профиля](../../rust/server/src/standalone_settings.rs) |
| Потоки ISBN | Индексатор читает `isbnThreads` перед очередной пачкой даже во время подготовки. Действуют ограничения машины и доступные фоновые слоты. [Цикл подготовки](../../rust/server/src/standalone_isbn.rs) |
| Кэш книг и обложек | Размеры дисковых кэшей и цель очистки используются при уборке. Изменение расписания будит планировщик. [Настройки кэша](../../rust/server/src/standalone_admin_cache.rs) |
| OPDS, Telegram и почта | OPDS меняет маршрут и параметры доступа для следующих запросов. Telegram и SMTP пересоздают затронутый канал. Значения интеграций, явно заданные окружением, имеют приоритет. [Настройки](../../rust/server/src/standalone_settings.rs) · [Каналы доставки](../../rust/server/src/standalone_delivery.rs) |
| Журнал событий, политика OTP и доверенные браузеры | Уже имеют отдельные действия администратора. Для настроек интерфейса `uiDefaults`, ссылки чтения и расширенного поиска сервер отдаёт актуальный конфиг при следующем `get-config`. [Команды сервера](../../rust/server/src/standalone_socket.rs) |
| Внешняя витрина и резервные копии | Общие параметры внешней витрины (источник, адрес, размер и срок кэша подборки) подхватываются при следующем обращении. Политика хранения и расписание резервных копий уже имеют своё управление. Размеры загрузки и распаковки резервной копии задаются при запуске. [Витрины](../../rust/catalog/src/reader_discovery.rs) · [Резервные копии](../../rust/server/src/standalone_backup.rs) |
| Источники библиотеки | Список можно сохранить во время работы. Чтобы изменения вошли в каталог, нужна переиндексация. Явный список из `INPX_LIBRARY_SOURCES` имеет приоритет над сохранённым. [Выбор источников](../../rust/catalog/src/library_sources.rs) |

## Что перенести

| Приоритет | Настройки | Как применять |
| --- | --- | --- |
| 1. Гостевой доступ | `INPX_ALLOW_ANONYMOUS_ACCESS`, с учётом `INPX_REQUIRE_AUTH` и `INPX_AUTH_MODE` | Для следующих HTTP-запросов и команд уже открытого WebSocket. На странице показать фактический режим. В локальном режиме `REQUIRE_AUTH=true` требует входа даже при разрешённых гостях. |
| 1. Доверенные прокси | `INPX_TRUST_PROXY`, `INPX_TRUSTED_PROXY_CIDRS` | Сохранять флаг и список IPv4/IPv6 одной операцией. Проверять целиком до записи. Показывать администратору IP непосредственного TCP-соединения и входит ли он в предложенный список. Открытые WebSocket должны пройти проверку по новой политике либо переподключиться. |
| 2. Нагрузка | Отдельные лимиты `INPX_RESOURCE_*`, параллельность конвертации, длина и таймаут очереди, максимальный размер книги для ISBN, период проверки INPX | Использовать существующий механизм смены лимитов. Параметры конвертации применять к следующим задачам, размер книги для ISBN — со следующей подготовки. При изменении интервала будить таймер проверки INPX. [Очереди](../../rust/server/src/standalone_resources.rs) · [Конвертер](../../rust/catalog/src/book_conversion.rs) |
| 2. Тест производительности | `INPX_RESOURCE_BENCH_ENABLED`, `INPX_RESOURCE_BENCH_TIMEOUT_MS` | Бенчмарк читает эти значения перед запуском. Сохранённый выбор можно применять со следующей проверки. [Бенчмарк](../../rust/server/src/standalone_benchmark.rs) |
| 2. Выдача книг | Форматы конвертации, MOBI, шаблоны названий, `INPX_JXL_DECODER`, включение онлайн-читалки | При смене форматов пересчитать доступные конвертеры и обновить одновременно меню скачивания, OPDS и выдачу файла. Для декодера применять выбор к новым запросам обложек. [Форматы](../../rust/catalog/src/book_conversion.rs) · [Обложки](../../rust/catalog/src/legacy_library_files.rs) |
| 3. Интеграции | Silero (`INPX_TTS_*`), KOReader (`INPX_KOSYNC_ENABLED`), Audiobookshelf (`INPX_ABS_*`), Prometheus (`INPX_METRICS_*`) | Эти компоненты создаются при старте. Для переключения нужны замена клиента или маршрута и обновление информации о доступных функциях. Для Silero отдельно определить судьбу текущего воспроизведения, для метрик и Audiobookshelf одновременно обновлять маршрут и его правила доступа. [Создание компонентов](../../rust/server/src/standalone.rs) |
| Отдельный этап доступа | Режим локального входа или SSO, имя заголовка прокси, привязка профиля, исключение для health, ограничения попыток входа | Изменять режим, заголовок и привязку согласованно. Сохранить возможность входа администратора и счётчики попыток при смене лимитов. [Проверки прокси](../../rust/server/src/request_access.rs) · [Доступ профилей](../../rust/server/src/standalone_access.rs) |

Адрес и порт слушателя, корневой URL, каталоги данных и временных файлов, путь к конфигу и веб-пакету стоит оставить параметрами запуска. Они определяют привязку сокета, маршруты или открытое хранилище. Пути к исполняемым файлам конвертеров лучше оставить владельцу установки. `--reset-admin-password` и `--recreate` — разовые операции. Фильтр INPX и режим экономии памяти связаны с построением и открытием индекса. Лимиты размера сообщения WebSocket, импорта и резервной копии стоит менять вместе, поскольку они участвуют в расчёте допустимого размера кадра. Параметры прежнего Node.js, например `queryCacheMemMb` и `dbCacheSize`, встречаются в совместимом экспорте. В Rust-сервере для них не найден обработчик изменения рабочего кэша. [Запуск standalone](../../rust/server/src/standalone.rs) · [Лимиты WebSocket](../../rust/server/src/standalone_socket.rs)

## Первый этап для библиотеки, конвертации и обложек

- **Библиотека и ISBN.** Оставить число потоков рядом с кнопкой подготовки. Рядом добавить ограничение размера одной книги для извлечения ISBN с подписью «Со следующей подготовки». Интервал проверки изменений INPX относится ко всей библиотеке. При его уменьшении или отключении планировщик должен пересчитать ближайшую проверку. [Индексатор](../../rust/server/src/standalone_isbn.rs) · [Планировщик](../../rust/server/src/standalone.rs)
- **Конвертация.** Показывать разрешённые форматы вместе с фактически найденными инструментами. Для AZW3 сервер проверяет наличие fb2cng, для PDF — MuPDF или Calibre, для MOBI — fb2cng и Kindling. В расширенных настройках отделить время ожидания в очереди от времени работы самого конвертера. Список форматов должен одинаково обновляться в карточке книги и OPDS. [Проверка форматов и очереди](../../rust/catalog/src/book_conversion.rs)
- **Обложки.** Выбор декодера JPEG XL применяется при следующем декодировании. Для проверки результата можно использовать существующую команду перестроения одной обложки. Размер дискового кэша уже меняется в админке. У кэша обложек в памяти предел 64 МиБ и срок хранения байтов 10 минут заданы константами. Настройка бюджета памяти была бы отдельной новой возможностью. [Декодер](../../rust/catalog/src/legacy_library_files.rs) · [Кэш в памяти](../../rust/server/src/standalone_download/cover_cache.rs)
- **Озвучка.** В отдельном разделе Silero объединить адрес, модель, ключ, таймаут и дисковую квоту. Для открытого плеера сохранить доступ к уже выданным ссылкам и фрагментам. Новый сервер и модель использовать для новых заданий. При смене модели кэш уже различает аудио по её имени. [Плеер, очередь и ключ кэша](../../rust/server/src/standalone_speech.rs)

## Что показала исходная проверка до внедрения

- **Гостевой доступ и сети прокси сегодня требуют перезапуска.** Через штатный админский импорт запретили гостей. Значение сохранилось, но и открытая вкладка, и новый гость продолжали получать книги через поиск. После перезапуска тот же запрос вернул `need_profile_login`. В отдельной операции убрали из доверенных адрес тестового Caddy. Новое WSS-соединение через него всё ещё получило `101`, после перезапуска — `403`. Для сравнения, отключение OPDS в том же процессе сразу изменило ответ маршрута с `200` на `404`.
- **У доступа несколько потребителей.** HTTP проверяет каждый запрос, WebSocket сохраняет результат допуска при открытии, а подсистема профилей держит собственный `require_profile`. При закрытии каталога следует проверить гостевой поиск, книгу, обложку, OPDS и уже открытую вкладку. При изменении сетей важно также проверить сохранённую привязку профиля прокси. [HTTP](../../rust/server/src/standalone.rs) · [WebSocket](../../rust/server/src/standalone_socket.rs) · [Профили](../../rust/server/src/standalone_access.rs)
- **Описание `REQUIRE_AUTH` расходится с Rust.** Инструкция по закрытой публикации описывает этот флаг в связке с режимом proxy, хотя в локальном режиме Rust тоже использует его для обязательного входа. При подготовке формы стоит уточнить инструкцию отдельно для Rust и классического Node.js. [Инструкция](../closed-publishing.md) · [Условие входа](../../rust/server/src/request_access.rs)
- **Импорт сообщает лишний перезапуск для ISBN.** Для одного `isbnThreads` он вернул `restartRequired=true`. При этом обработчик индекса читает актуальное значение на каждой пачке. Для админской формы и импорта стоит использовать общее правило применения. [Импорт](../../rust/server/src/standalone_settings.rs) · [Индексатор](../../rust/server/src/standalone_isbn.rs)
- **Запись произвольного ключа в JSON может потеряться.** Ручные `ttsModel` и `isbnMaxBookBytes` исчезли из файла после сохранения другой настройки. Загрузчик и запись отбирают поля по одному списку, в котором этих ключей нет. Перед переносом добавить поддерживаемые поля в схему, для ключа Silero — также в список секретов. Проверить сохранение, перезапуск и экспорт без секрета. [Схема](../../rust/catalog/config-fields.json) · [Чтение и запись](../../rust/catalog/src/configuration.rs)

Для первого выпуска предлагается раздел **Администрирование → Доступ и прокси**. У каждого поля показывать действующее значение и источник. Явный env для политики доступа остаётся под контролем владельца установки, а форму такого поля следует сделать доступной только для чтения. Это правило относится к доступу. Для профиля ресурсов и размеров кэша уже действует другой порядок, при котором сохранённый выбор администратора имеет приоритет. Перед сохранением проверять черновик, записывать конфиг и лишь после успешной записи переключать действующую политику целиком. Если новый список лишает текущего администратора доступа через его прокси, показать это до применения и предусмотреть возврат к предыдущей конфигурации. [Применение настроек](../../rust/server/src/standalone_settings.rs) · [Запись файла](../../rust/catalog/src/configuration.rs)

## Скрипт запуска Linux standalone

Проверена присланная копия `inpx-web (2).sh`. В тесте под обычным пользователем Linux заменили только путь установки на абсолютный временный каталог с релизным бинарником 2.0.2. `bash -n` прошёл. Два последовательных `start` оставили тот же PID, `restart` поднял новый процесс, `/ready` вернул `200`, а `stop` закрыл порт и убрал PID-файл.

| Строки | Что поправить перед включением в ZIP |
| --- | --- |
| 6–14, 24 | Вычислять абсолютный каталог скрипта. Пример `192.168.1.1/64` некорректен для IPv4. Один IPv4-адрес Caddy задаётся с `/32`, один IPv6 — с `/128`. Настройки доверия и входа должен выбирать владелец установки. |
| 19–38 | Последовательный повторный запуск работает. При двух одновременных `start` проверка PID и запись файла разделены. Нужна блокировка. `kill -0` спустя секунду подтверждает существование процесса, готовность каталога можно проверить по `/ready`. |
| 25 | `rm -f "$LOG_FILE"` уничтожает предыдущий журнал. В тесте контрольная запись исчезла после `restart`. Сохранять лог и при необходимости ротировать его. |
| 42–69 | Перед отправкой сигнала проверять, что PID принадлежит именно этому экземпляру. Устаревший PID может быть выдан другому процессу. Возвращать ошибку при неудачной остановке и продолжать `restart` только после подтверждённого завершения. |

Для Linux с systemd проще поставлять пример `.service`, где двоичный файл запускается напрямую и менеджер служб отслеживает процесс. Для NAS без systemd имеет смысл отдельный исправленный скрипт. [Документация systemd.service](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html)
