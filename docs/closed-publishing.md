# Закрытая публикация inpx-web

Для личной библиотеки включите обязательный вход в профиль, используйте HTTPS и ограничьте прямой доступ к порту контейнера. Если библиотека нужна только своим устройствам, можно оставить её в локальной сети и подключаться через VPN без публикации в интернете.

## 1. Подготовьте учётные записи

До включения ограничений создайте профиль с логином и паролем и проверьте вход. Замените стандартный пароль администратора, если он сохранился после обновления старой установки. Для повседневного чтения используйте обычный профиль.

`INPX_ADMIN_PASSWORD` задаёт начальный пароль при создании администратора; изменение этой переменной не меняет пароль уже существующего профиля. На новой установке без неё пароль генерируется и выводится в журнал запуска. Меняйте существующий пароль через управление профилями.

## 2. Включите обязательный вход

Добавьте к существующему `docker run`:

```sh
-e INPX_ALLOW_ANONYMOUS_ACCESS=false
```

В Docker Compose добавьте к сервису:

```yaml
environment:
  INPX_ALLOW_ANONYMOUS_ACCESS: "false"
```

Пересоздайте контейнер с прежними постоянными томами и остальными настройками. До входа будут доступны оболочка интерфейса и форма логина. Поиск, книги, обложки, личные данные и OPDS требуют авторизации. `/health`, `/ready` и `/api/index-status` остаются доступны для мониторинга; они не предоставляют доступ к книгам.

## 3. Ограничьте доступ к контейнеру

Если reverse proxy работает на том же хосте, публикуйте порт только на localhost:

```sh
-p 127.0.0.1:12380:12380
```

В этом случае proxy обращается к `http://127.0.0.1:12380`. Если proxy работает в другом контейнере, подключите оба контейнера к общей выделенной Docker-сети, уберите публикацию `ports` у inpx-web и направьте proxy на `http://inpx-web:12380`. Адрес `127.0.0.1` внутри proxy-контейнера указывает на сам proxy, а не на соседний контейнер.

Для proxy на другом сервере разрешите доступ к порту только с его адреса средствами сети или межсетевого экрана. Уберите проброс `12380` на маршрутизаторе. Во внешнем доступе оставьте HTTPS-вход через proxy; используйте действующий TLS-сертификат и поддержку WebSocket для `/ws` с учётом настроенного префикса URL.

## 4. Если нужно закрыть также оболочку интерфейса

Настройте Authelia/Authentik или другую авторизацию на reverse proxy. Чтобы inpx-web также проверял, что запрос пришёл от доверенного proxy с подтверждённым пользователем, добавьте:

```yaml
environment:
  INPX_ALLOW_ANONYMOUS_ACCESS: "false"
  INPX_REQUIRE_AUTH: "true"
  INPX_AUTH_MODE: "proxy"
  INPX_TRUST_PROXY: "true"
  INPX_PROXY_AUTH_HEADER: "Remote-User"
  INPX_TRUSTED_PROXY_CIDRS: "172.30.0.2/32"
```

`172.30.0.2/32` — пример адреса proxy, который видит приложение. Подставьте фактический стабильный адрес или минимальную необходимую подсеть выделенной сети. Не доверяйте произвольным адресам клиентов. Proxy должен удалять или перезаписывать входящий `Remote-User` и передавать имя только после успешной авторизации. Одних переменных контейнера без настроенного механизма входа на proxy недостаточно.

Применяйте авторизацию и передавайте заголовок пользователя для всех HTTP-запросов, а также подключения `/ws`, OPDS, книг и обложек. Если логин профиля совпадает с именем пользователя SSO, опция `INPX_PROXY_BIND_PROFILE=true` позволяет выбирать его автоматически. Иначе потребуется дополнительный вход в профиль.

Health-маршруты по умолчанию исключены из обязательной proxy-авторизации. Чтобы закрыть и их на уровне приложения, задайте `INPX_AUTH_EXEMPT_HEALTH=false` и адаптируйте мониторинг: анонимный health-check больше не получит успешный ответ. Явно включённые исключения для `/metrics` и отдельный токен провайдера Audiobookshelf настраиваются независимо; не публикуйте их без необходимости.

## 5. Подключите OPDS-клиент

OPDS поддерживает Basic-авторизацию по учётным данным профиля с включённой опцией авторизации OPDS либо общему логину и паролю из `opds.user` / `opds.password`. Используйте HTTPS; не помещайте пароль в URL.

Многие OPDS-клиенты не умеют проходить браузерную SSO-форму. Для них используйте доступ через VPN или предусмотренную вашим proxy проверку Basic-учётных данных. При включённом `INPX_AUTH_MODE=proxy` даже OPDS-запрос должен приходить от доверенного proxy с подтверждённым `Remote-User`: один Basic-заголовок не отменяет эту проверку. Не делайте анонимное исключение для OPDS, скачивания книг или WebSocket.

## 6. Проверьте результат

- В приватном окне браузера без cookie проверьте, что поиск и скачивание книги требуют входа. При SSO доступ к оболочке также должен требовать авторизации на proxy.
- Убедитесь с другого устройства, что порт `12380` не позволяет обойти proxy.
- После входа проверьте поиск, чтение, скачивание и подключение OPDS-клиента. При SSO проверьте также работу WebSocket и выбор профиля.
- Проверьте, что Docker health-check и мониторинг работают с выбранными ограничениями.

## Индексация и запросы к JS

Файлы `/app…/bundle.…js` содержат код веб-интерфейса; их загрузка необходима для работы страницы. При обязательном входе в профиль оболочка остаётся доступна без входа. При внешней авторизации её закрывает proxy.

Запрет индексации задаётся через `robots.txt` (`Disallow: /`) и HTTP-заголовок `X-Robots-Tag: noindex, nofollow`. Эти правила не заменяют авторизацию, не мешают сканеру игнорировать их и не гарантируют немедленное удаление ранее найденных страниц из поисковиков. Смена домена или префикса URL также не ограничивает доступ.
