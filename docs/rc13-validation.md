## Память и CPU

Одинаковая синтетическая нагрузка: десять профилей с PNG-фонами по 4 МиБ,
сохранение позиции администратора. Отдельный процесс на вариант, GC до и после;
создание/миграция файлов изображений не входит в измерение обычных операций.

| Метрика | rc.12 | rc.13 |
| --- | ---: | ---: |
| Файл состояния профилей | 53,38 МиБ | 48,92 КиБ |
| Наблюдаемый пик RSS | 695,76 МиБ | 57,15 МиБ |
| RSS после нагрузки и GC | 108,98 МиБ | 56,94 МиБ |
| Живой heap после GC | 58,62 МиБ | 6,42 МиБ |
| Среднее сохранение позиции | 552,59 мс | 7,97 мс |
| Среднее CPU-время сохранения | 567,67 мс | около 5 мс |

Пик снят таймером и на границах методов: это нижняя оценка. Короткие CPU-интервалы
на Windows имеют грубую точность. Эти результаты не являются обещанием задержки
на NAS или ограничением RSS всего сервера. Изображения перемещены на диск;
они сохраняются в переносимых бэкапах и доступны владельцу профиля.

Воспроизведение: `node scripts/profile-memory-benchmark.js`.
Исходные результаты до/после: [rc13-resource-results.json](./rc13-resource-results.json).

Начальные production JS/CSS: **1 753 148 → 1 017 493 байта**, примерно **−42%**
без транспортного сжатия. Классический поиск загружается при переходе на его маршрут.

## Границы

Рейтинги, ISBN и переиндексация по-прежнему могут использовать временные структуры
`O(N)` во время активного построения; ограничены завершённые кэши и декодированные
блоки. Фактический RSS зависит от V8, записей и параллельных операций. Старые SVG
оставлены inline для совместимости. Хранение прогресса остаётся в прежнем атомарном
JSON-формате, но изображения больше не копируются при обычном сохранении.
