# Подключение приложения

Кнопка QR в поисковой шапке веб-клиента открывает код адреса библиотеки. В INPX Reader нажмите «Сканировать QR». Формат `inpx-reader://connect?v=1&server=<URL>` содержит только HTTP/HTTPS-адрес с префиксом библиотеки, без паролей и токенов. После сканирования нужен обычный вход. При смене сервера приложение очищает прежние учётные данные.

HTTP разрешён с предупреждением о передаче пароля и данных без шифрования. HTTPS сохраняется; проверка сертификатов и origin остаётся включённой. Для HTTPS можно поставить перед INPX Web обратный прокси с сертификатом и поддержкой WebSocket.

Пароль профиля открывает личные позиции, полки и административные функции согласно роли. Общий пароль библиотеки — необязательный дополнительный барьер старого API (`need_access_token`, SHA-256 с солью), который не заменяет профиль. В приложении это дополнительное поле; оно открывается, когда его требует сервер.

## Возможности API v1

`get-config.clientApi = {version: 1, features: [...]}` объявляет следующие возможности. Без этого поля Android использует прежние команды и периодическую сверку; старые поля и ответы сохранены. Android передаёт `client: {type: "android", version: "0.10.0", protocol: 1}`; метрики группируются по ограниченному набору версий без идентификатора устройства.

| Feature | Контракт |
| --- | --- |
| `resumeSession` | `resume-user-profile {userId, profileAccessToken}` привязывает действительный токен к новой HTTP-cookie без пароля. Требуются CSRF и совпадение владельца. |
| `readerEvents` | `subscribe-client-events` подписывает вошедший профиль. Событие `{type: "client-event", kind: "reader"|"audio", bookUid}` не содержит пользовательских данных. Оно не отправляется автору изменения, гостю, другому профилю или неподписанному старому клиенту. Отзыв токена закрывает подписку. CAS не меняется. |
| `mobileHome` | `get-mobile-home {limit}` возвращает безопасные `profile`, `reading`, `lists`, `indexGeneration`; история ограничена 300. Подборки считаются отдельно. |
| `requestBudget` | Поиск/подборки: 4 расчёта одновременно, 1 на профиль/IP гостя, очередь 32, ожидание 30 секунд. Одинаковые запросы профиля разделяют расчёт. Перегрузка сохраняет `error` и добавляет `errorCode: "server_busy", retryAfterMs: 2000`. |
| `cancelAudio` | Отмена отдельного потребителя озвучки, см. ниже. |

## Отмена озвучки

Новый клиент передаёт уникальный `consumerId` (16–128 символов `[a-zA-Z0-9_-]`) в `prepare-reader-audio` / `preview-reader-voice`. Повторный опрос подготовки скачивания сохраняет идентификатор; явный запуск после отмены получает новый.

`cancel-reader-audio {consumerId}` требует профиль и CSRF. Отмена действует только для этого потребителя этого профиля, в том числе до завершения получения метаданных. Задание уходит из очереди; поздний ответ не создаёт его повторно. Общий синтез продолжается, пока его ждёт другой потребитель, включая старый веб-клиент. Готовый кэш сохраняется.

Для остановки работающего синтеза обновите также Silero. Основной сервер отправляет авторизованный `POST /jobs/<attemptId>/cancel`. Silero завершает текущий ограниченный вызов модели, останавливается между фрагментами, закрывает FFmpeg и освобождает слот. Старый Silero может не поддерживать отмену: основной сервер дождётся ответа и отбросит результат, сохраняя последовательность генерации. На старом основном сервере Android сообщает о недоступности отмены и прекращает местное ожидание/скачивание.

Android сохраняет отмену в WorkManager без паролей и токенов. Проверка поколения загрузки не позволяет прежнему worker возобновить отменённую или новую загрузку. Кнопка «Остановить», библиотека и уведомление используют одну цепочку отмены. Произвольные операции записи автоматически не повторяются.
