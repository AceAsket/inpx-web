# Прокси Telegram

В настройках интеграций доступны три режима:

- `system` — режим по умолчанию. Для HTTPS-запросов Telegram учитываются `HTTPS_PROXY` и затем `ALL_PROXY`; `NO_PROXY` разрешает прямое соединение для перечисленных адресов. Поддерживаются HTTP(S) и SOCKS5/5h. Для этих переменных регистр и приоритеты соответствуют `proxy-from-env`: строчные варианты имеют приоритет. `HTTP_PROXY` относится к HTTP-адресам, а Telegram использует HTTPS.
- `direct` — прямое соединение. Обходятся как настройки Axios, так и глобальный агент Node24 с `NODE_USE_ENV_PROXY`/`--use-env-proxy`.
- `custom` — отдельный прокси только для Telegram, независимо от системных `*_PROXY`/`NO_PROXY`. Указываются протокол, хост или IP, порт и при необходимости логин/пароль. URL с паролем в поле хоста не принимается.

HTTP-прокси использует CONNECT. HTTPS-прокси дополнительно шифрует соединение до самого прокси. SOCKS5 разрешает имя назначения локально; SOCKS5h передаёт имя назначения прокси. Выбор IP `auto`/`4`/`6` ограничивает соединение до прокси; при SOCKS5 он также применяется к локальному DNS назначения. При HTTP CONNECT и SOCKS5h IP назначения выбирает прокси. TLS-проверка сертификатов сохраняется; для частного центра сертификации используется стандартный механизм доверия Node, например `NODE_EXTRA_CA_CERTS`.

Одни настройки применяются к проверке `getMe`, polling/send API бота и отправке книг `sendDocument`, включая действие скачивания книги в боте. Ошибка авторизации или соединения с прокси не приводит к попытке обойти его прямым запросом. После изменения сети работающий бот переподключается. Проверка в интерфейсе сначала сохраняет выбранные настройки и затем вызывает `getMe`; она не отправляет сообщений.

Настройки можно задать переменными окружения `TELEGRAM_PROXY_MODE`, `TELEGRAM_PROXY_PROTOCOL`, `TELEGRAM_PROXY_HOST`, `TELEGRAM_PROXY_PORT`, `TELEGRAM_PROXY_USERNAME`, `TELEGRAM_PROXY_PASSWORD`. Явно заданные переменные имеют приоритет над сохранёнными полями. Системные proxy URL не сохраняются в настройках приложения. Режим и протокол сохраняются строками (`system`/`direct`/`custom`, `http`/`https`/`socks5`/`socks5h`), порт — целым числом 1–65535.

Пароль хранится в конфигурации через SecretStore в зашифрованном виде. Администратор получает `telegramProxyPasswordSet` и маркер `__KEEP__`; сам пароль не возвращается. Пропуск поля или `__KEEP__` сохраняет секрет, пустая строка/`null` очищает. Переключение в другой режим сохраняет предыдущие custom-поля для возврата к ним. Экспорт административных настроек пароль не содержит. Ошибки API и журнал WebSocket маскируют пароли, учётные данные в URL, Basic credentials и Telegram tokens; исходные объекты Axios с URL/config не передаются клиенту.

Реализация использует закреплённые CommonJS `https-proxy-agent` и `socks-proxy-agent`; SOCKS-переговоры выполняет `socks`, а не собственный протокол приложения. Node-зависимости импортируются только серверным transport. Shared-модуль содержит чистую валидацию для клиента и сервера.

`scripts/telegram-proxy-tests.js` проверяет реальные локальные HTTPS/CONNECT/SOCKS соединения, авторизацию, DNS/IPv6, отсутствие прямого fallback, системные переменные/NO_PROXY, обход native env agent, шифрование и повторную загрузку секрета, все API-пути и отмену зависшего handshake. Обращений к Telegram и реальных отправок в этих тестах нет.
