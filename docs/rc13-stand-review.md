# Проверка стенда RC.13, 7 ноября 2026

Стенд: `http://192.168.50.50:12380`, версия `1.8.2-rc.13`.
Проверка выполнялась через HTTP и административный WebSocket API, без SSH.

## Подтверждённый отказ

К началу замеров поток базы уже завершился после запуска встроенного теста
производительности. `/health` и вход продолжали работать; семь лёгких запросов
производительности за 60 секунд вернули `Worker does not exist (database closed?)`.
Поиск, чтение книг и дополнительную нагрузку после этого не запускали.

В одном снимке dashboard основной процесс имел RSS 543,5 МиБ, heap основного
потока 38,4 МиБ, event loop p95 2,22 мс. Это состояние после потери DB worker,
а не нормальный простой загруженной библиотеки. Метрики cgroup и DB heap получить
не удалось: опубликованный performance endpoint целиком завершался ошибкой.
Замеры не позволяют утверждать отсутствие утечек или оценить штатное потребление.

Причина в тестовой пробе `db.select({table:'book', limit:1})`: Jemba применяет
лимит после чтения и копирования выбранных строк. Локальная проверка показала
10 000 чтений ради одной возвращённой строки. Таймаут пробы также оставлял запрос
в работе, после чего запускались следующие пробы. Бюджет кэша блоков не ограничивает
такие временные результаты. После аварии следующие запросы обращались к закрытому
worker; автоматического восстановления не было.

## Правки в develop после публикации

- Проба ограничена первичным ключом, незавершённые пробы не перекрываются.
- Отказ DB worker останавливает тест, освобождает ожидающие запросы и сохраняет
  исходную причину. Не происходит автоматического повторения записей.
- Readiness учитывает доступность DB worker; метрики процесса и контейнера
  доступны даже при отказе базы.
- Добавлен тест своих лимитов параллельности с измерением CPU и памяти;
  сгенерированные параметры запуска воспроизводят проверенные лимиты.
- Клик по книге снова открывает превью; полная карточка доступна отдельно.
- Вкладки книги и загрузка автора используют общее оформление. Загрузка отзывов
  и оценок показывает проценты отдельных измеримых этапов; неизвестные объёмы
  остаются без выдуманного процента.

Опубликованный тег `v1.8.2-rc.13` этими правками не заменяется. Для повторного
измерения штатной нагрузки нужен запуск исправленной сборки со здоровым каталогом.
