# Подсказки каталога

Подсказки доступны с трёх Unicode-символов после нормализации и удаления пробелов по краям. Константа `MIN_SUGGEST_CHARS` в `shared/CatalogDiscovery.js` общая для клиента и сервера. Обычный поиск и Enter этим порогом не ограничиваются.

Подсказки соответствуют полю: «Название книги» отправляет `kind: 'title'` и показывает
книги, «Автор» — `author`, «Серия» — `series`. Сервер ищет только в выбранной
категории; исправления опечаток ограничены ею же. Клиент также отбрасывает лишние
категории из ответа старого сервера. Смешанный поиск остаётся доступен общим
поисковым полям, которые не передают `kind`; неизвестное непустое значение отклоняется.

Первый запрос использует уже существующие индексы `author`, `series`, `title` и `word`. Он не создаёт, не открывает и не ждёт дополнительную таблицу `catalog_lookup`. Раньше перед первым полезным ответом строился отдельный индекс: сервер читал все имена, серии и названия, разбирал слова и сохранял postings. На большой библиотеке эта работа зависела от общего размера каталога; клиент повторно получал только статус подготовки.

Текущий путь сначала ищет точное имя и начало имени, затем при необходимости использует существующий индекс слов для совпадений в середине названия или имени. Кандидаты проверяются общим сопоставлением слов. Ответ содержит до шести элементов каждого вида. Подсказки служат быстрым выбором нескольких вариантов; полный результат выдаёт обычный поиск.

Лимиты применяются до чтения строк и передачи данных из потока БД. Для каждого вида читается не более 32 прямых имён и 32 дополнительных имён, 16 строк слов, 64 книг из слов и 128 дополнительных книг для проверки фильтров/выбора издания. Из одной записи имени берутся не более четырёх распределённых идентификаторов книг. Полные большие postings не копируются. Книги передаются с явной проекцией полей для preview, чтения и скачивания; произвольные метаданные, аннотации и keywords остаются в БД.

Jemba 5.1.7 материализует весь диапазон в `dirtyIndexLR`, а обычный `select.limit` применяет после чтения строк. Поэтому ограниченный reader инкапсулирован в `CatalogLookupIndex`: бинарный поиск по уже загруженным sorted runs и слияние только ограниченного префикса. Если структура индекса не поддерживается, этот reader возвращает пустую ограниченную выборку и не переходит к полному сканированию. Регрессии проверяют поведение на реальной закреплённой версии Jemba.

Без дополнительных фильтров `count` берётся из точной статистики имени. С фильтрами число возвращается только тогда, когда проверены все книги кандидата. Иначе `count: null` и `limited: true` обозначают неполную выборку. Отсутствие элемента в таком ответе не означает отсутствие книг: пользователь может выполнить обычный поиск. Ответ не содержит процентов подготовки и не требует опроса сервера. Завершённый или уже выполняющийся старый lookup не используется и не изменяется новым запросом.

Исправления опечаток тоже используют ограниченный диапазон существующего индекса слов, а не обход словаря целиком. Кэш готовых ответов ограничен 100 записями и 8 МиБ, срок актуальности — 60 секунд; одинаковые одновременные запросы объединяются. Категория `kind` и фильтры входят в ключ: запрос того же слова в другом поле не использует чужие группы или исправления.

`scripts/catalog-suggest-fast-tests.js` проверяет exact/prefix, второе слово, кириллицу и `ё`, область фильтров, порог длины, несовместимый индекс и ограничения чтения на 30 тысячах совпадающих названий и posting автора в 30 тысяч книг. Запрещённые full scans, полные range reducers и запись нового индекса в этом сценарии приводят к падению теста.
