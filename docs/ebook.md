# Интерфейс для электронных книг и прогресс OPDS

Доступно начиная с версии `1.8.2-rc.15`.

В RC16 обновлены оформление, быстрый поиск по двум полям, добавлены личные
полки и применение формата скачивания профиля. RC15 содержит первоначальный
интерфейс.

## Совместимость браузеров электронных книг в RC17

Начиная с RC17 страницы занимают доступную ширину экрана, основной шрифт
увеличен с 17 до 22 px, подписи и элементы управления также увеличены.
Страницы проверяются без JavaScript на ширинах 320, 600 и 1072 px.
Подмена User-Agent в Chromium не воспроизводит движок физического Kindle;
проверка на устройстве остаётся необходимой.

«Файл: FB2» в выдаче обозначает исходный файл и больше не выглядит как
кнопка. У вошедшего профиля поиск, история, полка и карточка предлагают
отдельную ссылку «Скачать MOBI» или другой сохранённый формат.
Навигация и карточка `/ebook` остаются в простом интерфейсе: переходов
в обычную веб-версию нет. Скачивание и аннотация доступны прямо здесь.

Для старых браузеров скачивание использует обычную GET-ссылку. В её пути,
переходе по UID и конечном URL есть расширение файла. При выборе MOBI
конечный ответ имеет `.mobi` и `application/x-mobipocket-ebook`.
Заголовок `Content-Disposition` содержит безопасное ASCII-имя `filename`
и прежнее UTF-8-имя `filename*`: это [совместимый вариант по RFC 6266](https://www.rfc-editor.org/rfc/rfc6266.html#appendix-D).
Старые браузеры получают ASCII-имя с одной точкой перед расширением, современные сохраняют
имя на русском. Расширение старой ссылки и параметры запроса не меняют
текущий формат профиля.

Код `3c2a6e3666ebb06a62b437b339e567bf38fdb7ad` прошёл
[полный CI](https://github.com/AceAsket/inpx-web/actions/runs/42418980663):
427 регрессионных проверок, Linux/Windows, девять браузерных сценариев,
Docker lite/full и реальные конвертеры. В полном Docker-образе явно
включён MOBI для тестового профиля; проверены настоящая выдача MOBI,
имя без внутренних точек, MIME, Content-Length и расширение URL на каждом
переходе. Это не заменяет проверку загрузки на физическом Kindle.

## Простой интерфейс `/ebook`

Откройте `http://server:port/ebook`. Если приложение размещено под
`server.root=/library`, адрес будет `/library/ebook`.
Отдельного переключателя в настройках нет.

Это серверные HTML-страницы с обычными ссылками и GET/POST-формами.
JavaScript, WebSocket, внешние шрифты и анимация не нужны.
Белый фон, чёрный текст и крупные элементы рассчитаны на браузеры разных
электронных книг; проверка конкретных аппаратных моделей ещё не проводилась.
Основной сценарий — найти книгу и скачать её для штатной читалки устройства.

- Поиск по названию, автору или серии запускается кнопкой. Пустая стартовая
  страница не просматривает всю библиотеку, автоподсказок и фонового опроса нет.
- Кнопка «Параметры поиска» открывает отдельную форму: совпадение всех слов,
  фразы или точной записи, язык, формат, источник, 10/20 книг на странице.
  Введённый запрос сохраняется при переходе к параметрам.
- Обложки по умолчанию выключены. Их можно включить в параметрах выдачи.
  Аннотация загружается по отдельной кнопке в карточке.
- Автор и серия ведут к поиску. Переходы к книге, тексту и обратно сохраняют
  фильтры и страницу каталога.
- «Скачать книгу» использует существующий обработчик скачивания. Список
  форматов зависит от настроек сервера и конвертеров.
- «Сейчас читаю» показывает историю текущего вошедшего профиля.
  Вход и выход работают обычными формами; существующие ограничения доступа
  к библиотеке, пароли профилей и привязка SSO сохраняются.

В качестве ориентира изучен режим `/lite` проекта
[inpx-library-server](https://github.com/Habsaec/inpx-library-server/blob/master/src/routes/lite.js):
отдельный HTML-интерфейс и обычная навигация. `/ebook` использует поиск,
профили, аннотации и скачивание текущего проекта. Набор возможностей
референса не копируется целиком.

## Быстрый поиск и личные полки в RC16

На начальной странице доступны отдельные поля «Название книги» и «Автор».
Можно заполнить любое из них или оба: условия объединяются. Расширенные
параметры сохраняют поиск по серии, языку, формату и источнику. Техническая
подпись о JavaScript убрана; навигация и выдача получили общее чёрно-белое
оформление без загрузки дополнительных файлов.

«Мои полки» показывает личные списки и умные полки вошедшего профиля,
включая неопубликованные в OPDS. Обычная полка читает только 10/20 записей
текущей страницы; отсутствующая книга не получает кнопку скачивания.
Список полок не пересчитывает умные запросы. Умная полка выполняет поиск
при открытии; для непрочитанных проверяется максимум 200 записей за запрос,
после чего доступно продолжение. Навигация сохраняет позицию; из карточки
можно вернуться к полке. Чужой ID списка возвращает 404, незавершённый ответ
после выхода не раскрывает данные прежнего профиля.

## Формат скачивания в RC16

В карточке и на полке доступен выбор формата с кнопкой «Сохранить формат».
Он сохраняется в `defaultDownloadFormat` текущего профиля, применяется
также к последующим книгам и меняется POST-формой с CSRF. Это настройка
канала скачивания: Email, Telegram и OPDS имеют свои настройки.

Кнопки на полке скачивают книгу одним нажатием. `/ebook/download` заново
читает выбор профиля при каждом запросе, поэтому старый URL не может
переопределить его параметром `format`. Существующий обработчик получает
явный конечный формат. Если выбранный формат совпадает с исходным, выдаётся
оригинал этого же формата. Для другого формата используется конвертация.
Если она недоступна, кнопка заменяется пояснением, прямой запрос получает
415. При ошибке конвертера оригинальный FB2 вместо выбранного EPUB не
подставляется. Неавторизованный посетитель выбирает доступный формат
в карточке для конкретного скачивания.

## Необязательное текстовое чтение

«Читать текст» доступно для поддерживаемых локальных книг, когда серверная
читалка включена. FB2 читается потоком; EPUB сначала подготавливается
существующим конвертером, если он доступен. Остальные форматы скачиваются.
Страница передаёт около 3000 символов текста без иллюстраций. Кнопки
«Предыдущая», «Следующая» и три размера шрифта работают без JavaScript.

Место сохраняется в URL страницы: его можно добавить в закладки браузера.
Этот режим не записывает прогресс полной веб-читалки. Автоматической
синхронизации с нативной читалкой устройства также нет.

Ограничения подготовки: исходный и распакованный XML до 32 МиБ, текст до
2 Ми символов, глубина XML до 128. Один активный разбор и три ожидающих
запроса; одинаковые запросы объединяются. Кэш текста — до 16 МиБ,
восьми книг и пяти минут, ключ учитывает поколение библиотеки и книгу.
Временный FB2 удаляется после разбора. При закрытии базы активное чтение
прерывается, кэш очищается. Для извлечения и разбора действует бюджет 30 с;
подготовка EPUB дополнительно зависит от ограничений общего конвертера.
При превышении ограничений остаётся доступно скачивание оригинала.

HTML-ответы имеют `Cache-Control: private, no-store`, запрет сценариев и
встраивания во фрейм. Пароли не помещаются в URL, POST-формы проверяют CSRF.
Поздний ответ истории после выхода из профиля отклоняется.

## Отметки в OPDS

В персональных OPDS-лентах перед названием книги отображается прогресс
выбранного профиля:

| Отметка | Прогресс |
| --- | --- |
| без отметки | Нет позиции или 0% |
| ◔ | Больше 0%, до 25% включительно |
| ◑ | Больше 25%, до 50% включительно |
| ◕ | Больше 50%, меньше 99,9% |
| ⬤ | Прочитана: от 99,9% или существующая отметка прочтения |

Порог прочитанного совпадает с полной читалкой. Позиции, перенесённые на
другую книгу, не отмечают прежнюю запись. Скрытие из истории не удаляет
саму позицию.

Прогресс берётся из профиля, уже проверенного обработчиками OPDS. Это
распространяется на поиск, выдачи книг, списки и полную карточку.
Навигационные разделы не получают отметок. Ссылки внутри OPDS сохраняют
выбранный профиль. Персональные ответы запрещено помещать в общий HTTP-кэш.
Общий каталог без выбранного профиля не подставляет прогресс администратора.
В закрытом режиме личный контекст определяется входом или OPDS Basic Auth.

Название меняется только при формировании ленты. UID, запись базы, ссылки
скачивания и общие кэши остаются прежними. Дополнительного сканирования
каталога или чтения книг для отметок нет: используется прогресс профиля и
готовые записи текущей страницы. Получить прогресс из сторонней читалки
можно только при наличии отдельной поддерживаемой синхронизации; обычное
скачивание через OPDS само по себе его не сообщает.

## Проверка

`scripts/ebook-tests.js` проверяет формы, фильтры, доступ, CSRF, поздние
ответы, потоковый разбор XML/gzip, кодировки, Unicode, лимиты и кэш.
`scripts/opds-progress-tests.js` проверяет ступени прогресса, изоляцию
профилей, XML, ссылки и заголовки кэширования.
Оба набора включены в `test:release`.

`scripts/ebook-browser-test.js` запускает настоящий сервер с тестовой INPX
и Chromium с отключённым JavaScript. Проверяет вход, отдельную форму
параметров, поиск, пагинацию, аннотацию, скачивание оригинала, чтение,
выход и геометрию 600/320 px. Тестовая Node-программа отдельно сохраняет
прогресс через API и проверяет настоящие OPDS-выдачи и карточки для всех
четырёх отметок. Сама страница устройства не открывает WebSocket.
Сценарий включён в CI; проверка упакованных приложений также открывает
`/ebook`, чтобы обнаружить отсутствующие модули при упаковке.

Локально 7 ноября 2026: полный `test:release` — 416 проверок, PASS;
production-сборка клиента — PASS (три прежних предупреждения размера
bundle); браузерный сценарий `/ebook` и настоящего OPDS — PASS.
Отдельно проверено прерывание извлечения и освобождение текстового кэша
при закрытии базы. Артефакты: `.review-tmp/ebook/browser-complete/`.
Сквозная проверка также выявила и закрыла ошибку OPDS-карточки FB2 без
атрибутов у корневого элемента; варианты с `l` и `xlink` проверены отдельно.
